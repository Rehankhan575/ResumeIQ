## 1. Goal & Architectural Purpose

The skills taxonomy (`data/taxonomies/skills.csv`) provides the foundation for the **Rule-Based NER Extractor** in Stage 2 / Step 3a (`app/extraction/skills.py`).

To ensure balanced evaluation across all 24 LiveCareer categories (both technical and non-technical domains such as Healthcare, Accounting, Education, Sales, Fitness, Culinary Arts, Legal, and HR), the taxonomy combines high-precision hand-curated domain vocabularies with validated occupational software skills and annotated entity strings.

## 3. Taxonomy Schema & Normalisation Rules

### File Structure (`data/taxonomies/skills.csv`)

| Column | Type | Description |
|:---|:---|:---|
| `skill` | `string` | Canonical skill name (lowercase, trimmed whitespace). |
| `aliases` | `string` | Pipe-separated (`\|`) list of alternate expressions (e.g. `py\|python3`). Empty if none. |
| `category` | `string` | Domain category (e.g. `programming_languages`, `accounting_finance`). |
| `source` | `string` | Provenance: `curated`, `onet`, or `ner_synthetic`. |

### Normalisation Rules
1. **Lowercase & Strip**: All keys and aliases are normalized to lowercase with extraneous whitespace stripped.
2. **Single-Character Allowlist**: Single-character entries are strictly forbidden unless member of `{'c', 'r', 'go'}`.
3. **No Duplicate Primary Keys**: Each canonical skill appears exactly once in `skills.csv`.
4. **Disjoint Alias Mapping**: Every alias maps to exactly **one** skill. No alias is permitted to collide with any canonical skill name or with an alias of another skill.
5. **Length Cap**: O*NET entries exceeding 4 words are dropped to eliminate non-atomic descriptions.

## 4. Ambiguity Handling (`data/taxonomies/ambiguous_terms.csv`)

Certain technical skills collide directly with ordinary English words, prepositions, or broad business terms. To prevent false positives in the rule-based extractor (Step 3a), each term is mapped to an enforcement rule:

| Term | Category | Rule | Justification & Disambiguation Strategy |
|:---|:---|:---|:---|
| `c` | `programming_languages` | `require_context` | Collides with middle initials, grades, section headers. Requires programming context (e.g., `C/C++`, `C programming`). |
| `r` | `programming_languages` | `require_context` | Collides with registered trademarks or single letters. Requires stats/programming context (`R package`, `R programming`). |
| `go` | `programming_languages` | `require_context` | Collides with common verb "to go". Requires programming terms nearby or alias `golang`. |
| `java` | `programming_languages` | `case_sensitive` | Collides with geographic island or coffee. Must match capitalized `Java` and avoid substring collisions in `javascript`. |
| `swift` | `programming_languages` | `require_context` | Collides with adjective "swift" or banking protocol SWIFT. Requires iOS/Apple/programming context. |
| `rust` | `programming_languages` | `require_context` | Collides with corrosion/oxidation. Requires software engineering context. |
| `spark` | `data_ml_dl` | `require_context` | Collides with noun/verb "spark". Requires big data context (`Apache Spark`, `PySpark`). |
| `excel` | `software_tools` | `require_context` | Collides with verb "to excel". Requires spreadsheet, Microsoft, or office context. |
